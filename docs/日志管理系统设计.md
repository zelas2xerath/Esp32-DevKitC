# ESP32 土壤监测系统 - 日志管理设计

## 1. 概述

为了优化系统性能，增强程序的健壮性，我们使用 ArduinoLog 库实现了一个完整的日志管理系统，替代直接使用 `Serial.println` 的方式。日志系统通过分级管理日志输出，可以显著减少系统开销，并提供更好的错误管理能力。

## 2. 系统架构

### 2.1 模块组成

- **LogManager**: 核心日志管理模块，封装 ArduinoLog 库
- **CommandProcessor 的 LogLevelHandler**: 提供远程控制日志级别功能
- **Flash 存储**: 保存日志配置，确保重启后配置不丢失

### 2.2 关键功能

- 日志分级（SILENT → FATAL → ERROR → WARNING → NOTICE → TRACE → VERBOSE）
- 自定义日志前缀（时间戳 + 日志级别）
- 支持格式化字符串输出
- 远程控制日志级别
- 配置持久化存储

## 3. 日志级别设计

| 级别    | 枚举值 | 说明                           | 典型应用场景                           |
|---------|-------|--------------------------------|--------------------------------------|
| SILENT  | 0     | 无日志输出                     | 生产环境，最大化性能                   |
| FATAL   | 1     | 致命错误（导致系统不可用）     | 系统崩溃、硬件故障                     |
| ERROR   | 2     | 错误（功能受影响但可继续运行） | 网络连接失败、传感器读取错误           |
| WARNING | 3     | 警告（潜在问题）               | 阈值接近边界、配置不理想               |
| NOTICE  | 4     | 提示（重要状态变化）           | 设备启动、模式切换、阈值更改           |
| TRACE   | 5     | 跟踪（程序执行流程）           | 函数调用、模块初始化                   |
| VERBOSE | 6     | 详细（完整调试信息）           | 所有细节信息，包括循环状态、数值变化等 |

## 4. 使用方式

### 4.1 代码中使用

```cpp
// 初始化（默认NOTICE级别）
LogManager::begin();

// 不同级别日志
LOG_FATAL("系统致命错误: %s", errorMsg);
LOG_ERROR("网络连接失败: %d", errorCode);
LOG_WARNING("湿度接近阈值: %d%%", moisture);
LOG_NOTICE("设备已启动，版本: %s", VERSION);
LOG_TRACE("初始化传感器完成");
LOG_VERBOSE("ADC读数: %d", adcValue);
```

### 4.2 动态调整日志级别

可以通过指令远程调整日志级别：

```
LOG_LEVEL-3  // 设置为WARNING级别
```

| 指令格式        | 说明               |
|----------------|-------------------|
| LOG_LEVEL-0    | 关闭所有日志输出   |
| LOG_LEVEL-1    | 仅输出致命错误     |
| LOG_LEVEL-2    | 输出错误级别及以上 |
| LOG_LEVEL-3    | 输出警告级别及以上 |
| LOG_LEVEL-4    | 输出提示级别及以上 |
| LOG_LEVEL-5    | 输出跟踪级别及以上 |
| LOG_LEVEL-6    | 输出所有级别日志   |

## 5. 性能提升

相较于原始的 `Serial.println` 方式，日志管理系统带来以下性能提升：

1. **减少串口通信量**：根据日志级别过滤不必要的输出，减少串口通信量约 60-80%
2. **降低 CPU 占用**：避免了字符串处理和格式化的开销
3. **降低内存使用**：格式化字符串减少了临时字符串的创建

## 6. 错误管理提升

1. **错误分级**：明确区分不同严重程度的错误
2. **统一格式**：时间戳 + 错误级别 + 详细信息
3. **错误追踪**：可以追踪错误发生的时间和上下文

## 7. 最佳实践

1. 合理选择日志级别：生产环境使用 WARNING 或 NOTICE 级别
2. 避免在高频循环中使用 VERBOSE 级别日志
3. 使用格式化字符串提高可读性
4. 在关键节点记录 NOTICE 级别日志，便于问题定位
