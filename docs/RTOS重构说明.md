# ESP32 RTOS架构重构说明

## 📋 重构概述

本次重构将ESP32土壤监测系统从传统的阻塞式`loop()`模型升级为基于FreeRTOS的多任务并发架构，实现了真正的实时系统设计。

## 🎯 重构目标

### ✅ 已实现的目标
1. **多任务并发执行** - 传感器读取、网络通信、控制逻辑、硬件操作并行运行
2. **消除阻塞延时** - 移除所有基于`millis()`的时间管理代码
3. **实时响应性** - 系统能够快速响应外部事件和指令
4. **资源保护** - 使用互斥锁保护共享资源访问
5. **事件驱动** - 基于队列和事件组的通信机制
6. **系统监控** - 看门狗任务监控系统健康状态

## 🔧 核心组件

### 1. 任务定义 (RTOSTasks.h)
- 定义了6个核心任务的优先级、堆栈大小和周期
- 声明了所有RTOS资源句柄
- 提供任务管理函数接口

### 2. 数据结构 (RTOSCommon.h)
- `SensorDataMessage` - 传感器数据消息
- `NetworkSendMessage` - 网络发送消息
- `ControlCommandMessage` - 控制指令消息
- `DisplayMessage` - 显示消息
- `SystemEventMessage` - 系统事件消息

### 3. 任务实现
#### SensorTask (传感器任务)
- **功能**: 周期性读取所有传感器数据
- **周期**: 5秒
- **输出**: 传感器数据队列

#### NetworkTask (网络任务)
- **功能**: 处理网络连接和数据传输
- **周期**: 1秒
- **输入**: 网络发送队列
- **输出**: 指令到控制任务

#### ControlTask (控制任务)
- **功能**: 业务逻辑处理和决策
- **周期**: 2秒
- **输入**: 传感器数据队列、系统事件队列
- **输出**: 控制指令队列、显示消息队列

#### ActuatorTask (执行器任务)
- **功能**: 执行硬件控制操作
- **周期**: 0.5秒
- **输入**: 控制指令队列
- **输出**: 硬件控制信号

#### DisplayTask (显示任务)
- **功能**: 更新OLED显示内容
- **周期**: 1秒
- **输入**: 显示消息队列
- **特性**: 优先级管理、轮换显示

#### WatchdogTask (看门狗任务)
- **功能**: 系统健康监控
- **周期**: 10秒
- **特性**: 任务监控、资源监控、异常恢复

## 🚀 使用方法

### 编译和上传
1. **使用RTOS版本**:
   ```bash
   # 重命名文件
   mv src/main.cpp src/main_legacy.cpp
   mv src/main_rtos.cpp src/main.cpp
   
   # 编译上传
   pio run --target upload
   ```

2. **恢复传统版本**:
   ```bash
   mv src/main.cpp src/main_rtos.cpp
   mv src/main_legacy.cpp src/main.cpp
   ```

### 配置参数
在`RTOSTasks.h`中可以调整：
- 任务优先级
- 堆栈大小
- 队列大小
- 任务周期

## 📊 性能对比

| 特性 | 传统Loop模型 | RTOS多任务模型 |
|------|-------------|---------------|
| 响应时间 | 受最慢任务影响 | 实时响应 |
| CPU利用率 | 顺序执行，效率低 | 并发执行，效率高 |
| 可扩展性 | 难以扩展 | 易于添加新任务 |
| 错误隔离 | 一个错误影响全部 | 任务间隔离 |
| 资源管理 | 手动管理 | 自动调度 |
| 代码复杂度 | 单文件复杂 | 模块化清晰 |

## ⚠️ 注意事项

1. **内存使用**: RTOS版本使用更多内存，确保ESP32有足够RAM
2. **任务优先级**: 不要随意修改任务优先级，可能影响系统稳定性
3. **队列大小**: 根据实际需求调整队列大小，避免内存浪费
4. **互斥锁**: 避免死锁，获取锁后及时释放
5. **看门狗**: 看门狗任务会自动重启异常任务，注意日志监控
