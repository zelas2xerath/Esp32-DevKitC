# ESP32-DevKitC 错误处理系统说明

## 错误处理架构

ESP32-DevKitC项目采用了统一的错误处理机制，主要由SystemManager集中管理，同时在各个组件中实现一致的错误处理接口。

### 1. 错误码体系

系统使用`ErrorCode`枚举类型表示各种错误状态，基本分为以下几类：

- **SUCCESS**：操作成功
- **系统级错误**：如资源不可用、参数错误等
- **硬件级错误**：如传感器读取失败、通信错误等
- **应用级错误**：如配置错误、状态错误等
- **严重错误**：可能导致系统无法正常工作的错误

### 2. 错误处理机制

#### 2.1 SystemManager错误处理

SystemManager作为系统的核心组件，负责全局错误状态的管理，实现了以下关键方法：

- `reportError(ErrorCode code, const char* message, SystemState severity)`: 报告并记录错误
- `getLastErrorCode()`: 获取最近一次错误码
- `getLastErrorMessage()`: 获取最近一次错误信息
- `clearLastError()`: 清除错误状态
- `setSystemState(SystemState state, ErrorCode errorCode, const char* errorMessage)`: 设置系统状态并记录相关错误信息

#### 2.2 组件级错误处理

各组件（如SensorManager、NetworkManager等）都实现了统一的错误处理接口：

- `reportError(ErrorCode code, const String& message)`: 报告并记录错误
- `getLastErrorCode()`: 获取组件最近一次错误码
- `getLastErrorMessage()`: 获取组件最近一次错误信息
- `clearLastError()`: 清除组件错误状态

### 3. 错误状态查询

系统提供多种方式查询错误状态：

#### 3.1 系统状态查询

- `getSystemStatus()`: 获取包含错误信息的系统状态字符串
- `showSystemStatus()`: 在OLED上显示系统状态

#### 3.2 网络接口查询

通过命令处理器提供了以下错误状态查询命令：

- `NET_QUALITY`: 查询网络质量及相关错误
- `STATE_HISTORY`: 查询系统状态历史及错误信息

### 4. 错误处理流程

1. **错误检测**：各组件在操作过程中检测到错误
2. **错误报告**：调用`reportError`记录错误信息并返回错误码
3. **错误传播**：返回错误码给调用者，同时可能触发系统状态变更
4. **错误处理**：SystemManager根据错误严重程度进行相应处理（如显示错误信息、设置系统状态等）
5. **错误恢复**：系统可能尝试自动恢复或提供手动恢复机制

### 5. 扩展和使用指南

#### 5.1 添加新错误码

在`lib.h`中扩展`ErrorCode`枚举：

```cpp
enum class ErrorCode {
    SUCCESS = 0,
    // ... 现有错误码 ...
    NEW_ERROR_CODE = XX, // 添加新的错误码
};
```

#### 5.2 错误处理最佳实践

- **提供详细信息**：错误信息应当清晰描述问题
- **适当的严重程度**：根据错误影响设置合适的系统状态
- **链式调用**：`return reportError(...)`同时报告错误并返回错误码
- **错误恢复**：为关键错误提供恢复机制

#### 5.3 使用示例

```cpp
// 检测并报告错误
if (!sensorReady) {
    return reportError(ErrorCode::SENSOR_NOT_READY, "传感器未就绪");
}

// 查询错误状态
if (component->getLastErrorCode() != ErrorCode::SUCCESS) {
    LOG_WARNING("组件出现错误: %s", component->getLastErrorMessage().c_str());
}

// 错误恢复
if (networkManager->getLastErrorCode() == ErrorCode::WIFI_CONNECTION_ERROR) {
    networkManager->reconnect();
    networkManager->clearLastError();
}
```
